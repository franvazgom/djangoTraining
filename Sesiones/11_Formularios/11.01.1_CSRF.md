# Ataque CSRF
1. Sesión Activa: El usuario inicia sesión en una aplicación vulnerable (ej: banco.com). El servidor le entrega una cookie de sesión que el navegador guarda para no pedir la contraseña en cada clic.
2. El Cebo: Sin cerrar la sesión del banco, el usuario visita un sitio malicioso controlado por el atacante (o un sitio legítimo infectado).
3. La Carga Útil: El sitio del atacante contiene un formulario oculto o un script (JavaScript) que apunta a una acción específica en el banco, por ejemplo: ://banco.com.
4. El Disparo: El sitio malicioso hace que el navegador del usuario envíe esa solicitud automáticamente al banco.
5. La Trampa Funciona: Como el navegador siempre envía las cookies asociadas a un dominio cuando hace una petición a ese dominio, el banco recibe la solicitud junto con la cookie de sesión del usuario.
6. Ejecución: El servidor del banco ve la cookie válida, cree que el usuario hizo la transferencia voluntariamente y procesa el robo.

## Mitigación
Tokens Anti-CSRF (La más común)

El servidor genera un código único y secreto (token) que se incluye en cada formulario. Cuando el usuario envía el formulario, el servidor compara el token recibido con el que él tiene guardado. Como el atacante no puede "leer" el token del sitio real, no puede incluirlo en su petición falsa.
