Hasta ahora lo que hemos estado haciendo es crear el template, crear el método correspondiente en el view y finalmente configurar el archivo urls.py

El archivo urls, puede ir creciendo y el proyecto volverse poco escalable. Por lo que es recomendable que cada aplicación, tenga su propio archivo urls. 

¿Qué pasaría si en otra aplicación se tiene el nombre “visit_us”?

+ Es una buena práctica colocar el nombre de la aplicación en el urlpatterns del archivo urls.py 
+ Esto con el objetivo de evitar ambiguedad en el caso de existir 2 o más referencias con el mismo nombre


# Configuración URLS - Práctica
1. Dentro la aplicación core, crear el archivo urls.py
```python
from django.urls import path
from core import views

core_urlpatterns = ([
    path('', views.home, name='home'),
    path('about/', views.about, name='about'),
    path('visit_us/', views.visit_us, name='visit_us'),
], 'core')

```
2. En el archivo urls.py del proyecto, modificarlo de la siguiente manera: 
```python
from django.urls import path, include
from core.urls import core_urlpatterns

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include(core_urlpatterns)),    
]
```
3. Es necesario cambiar la referencia desde el archivo base.html en el navbar
```python
{% url 'core:home' %}
```
