# Permisos
En Django, el sistema de permisos está integrado directamente con la arquitectura de los modelos. Es un sistema robusto basado en el modelo Permission (de la app nativa django.contrib.auth).

Cada vez que creas y migras un modelo en Django, el framework genera automáticamente 4 permisos básicos por cada modelo, utilizando la siguiente estructura de nombres internos (codename):

+ add_<modelo> (Añadir)
+ change_<modelo> (Editar/Modificar)
+ delete_<modelo> (Eliminar)
+ view_<modelo> (Ver - Introducido en Django 2.1)

Por ejemplo, para tu modelo Order, Django crea internamente los permisos: add_order, change_order, delete_order y view_order.

## Privilegios mediante código
1. Opción 1: En el archivo views.py de services 
```python
from django.contrib.auth.decorators import permission_required
from django.core.exceptions import PermissionDenied

@staff_member_required()
@permission_required('services.change_service', raise_exception=True)
def create(request):
    ... 
```
2. Verificar funcionamiento
3. Opción 2: En el archivo views.py de services 
```python
if not request.user.has_perm('services.change_service'):
        raise PermissionDenied('No tienes los privilegios suficientes')
```
4. Verificar funcionamiento
5. Opción 3, desde las plantillas. En las plantillas (templates) de Django no se pueden invocar funciones pasando argumentos con paréntesis como has_perm('...')., para solucionar esto de forma elegante, Django expone automáticamente una variable especial en el contexto de los templates llamada perms. Reemplza: {% if request.user.is_staff %} por: 
```python
{% if perms.services.change_service %}
```
6. Verificar funcionamiento
